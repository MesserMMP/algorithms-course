# Merge lists

`solution.py` содержит `ListNode(val, next)`, `merge_with_dummy(list1, list2)`
и `merge_without_dummy(list1, list2)`. Обе функции возвращают голову
результата либо `None`. Python 3.10+, внешних зависимостей нет.

Входы — отсортированные по неубыванию односвязные списки без циклов
и общих узлов. Пустой список задаётся `None`. Числа могут повторяться.
**Функции изменяют связи исходных узлов.** «Новый список» — новая цепочка
из тех же узлов, а не копия: исходные списки после вызова не следует
использовать как независимые структуры. Для сравнения двух реализаций
создайте входы заново.

## Идея и корректность

Пока оба списка непусты, выбираем меньшую голову, присоединяем её
к `tail` и сдвигаем указатель выбранного списка. При равных значениях
берём list1, сохраняя порядок равных элементов. Когда один вход исчерпан,
одним присваиванием присоединяем остаток второго.

- **С фиктивным элементом:** начинаем с `dummy = ListNode()` и `tail = dummy`.
  Первый узел добавляется так же, как остальные. Возвращаем `dummy.next`;
  сам dummy в результат не входит.
- **Без фиктивного элемента:** отдельно обрабатываем пустые входы,
  затем выбираем меньшую голову как `head = tail`. Дальше цикл тот же.
  Возвращаем head. Новые узлы вообще не создаются.

Инвариант: выбранный префикс результата отсортирован и состоит из уже
обработанных исходных узлов, tail указывает на последний выбранный узел.
Необработанные части начинаются с list1 и list2. Меньшая из двух голов —
минимальный оставшийся элемент, поэтому её выбор сохраняет инвариант.
Остаток второго списка отсортирован и не меньше хвоста выбранного
префикса: его можно присоединить целиком. Каждый узел включён ровно один раз.
Во время работы `tail.next` может ещё указывать в исходную цепочку;
окончательную связь задаёт следующий шаг.

## Сложность

Оба способа: **O(n + m)** времени в худшем случае, **O(1)** дополнительной
памяти. Указатели продвигаются вперёд, копий списков нет. Dummy — один
вспомогательный узел, его размер не зависит от входов. Рекурсии нет.
Если один список изначально пуст, возврат / присоединение занимает O(1).

## Пошаговая визуализация

Входы: `A1(1) → A2(2) → A3(4)` и `B1(1) → B2(3) → B3(4)`.
ID обозначает **тот же объект** до и после слияния.
Таблица показывает выбранный префикс, а не все временные связи `next`.

| Шаг | Сравнение / действие | Выбранный префикс | Следующие головы |
| --- | --- | --- | --- |
| 0 | Начало | ∅ | A1(1), B1(1) |
| 1 | 1 ≤ 1, берём A1 | A1(1) | A2(2), B1(1) |
| 2 | 2 > 1, берём B1 | A1(1) → B1(1) | A2(2), B2(3) |
| 3 | 2 ≤ 3, берём A2 | A1(1) → B1(1) → A2(2) | A3(4), B2(3) |
| 4 | 4 > 3, берём B2 | A1(1) → B1(1) → A2(2) → B2(3) | A3(4), B3(4) |
| 5 | 4 ≤ 4, берём A3 | A1(1) → B1(1) → A2(2) → B2(3) → A3(4) | None, B3(4) |
| 6 | Присоединяем B3 | A1(1) → B1(1) → A2(2) → B2(3) → A3(4) → B3(4) | — |

С dummy на шаге 0 `tail = dummy`, на шаге 1 `dummy.next = A1`.
Без dummy на шаге 1 `head = tail = A1`. Шаги 2–6 одинаковы.
Результат: `[1, 1, 2, 3, 4, 4]`. В обоих случаях возвращён **A1**.
Интерактивная версия в `../visualization/` переключает оба способа
и сохраняет ID / цвет узлов. Она также показывает выбранный префикс.

## Пример использования

```python
from homework_2.merge_lists.solution import ListNode, merge_with_dummy

list1 = ListNode(1, ListNode(2, ListNode(4)))
list2 = ListNode(1, ListNode(3, ListNode(4)))
head = merge_with_dummy(list1, list2)
while head is not None:
    print(head.val)
    head = head.next
```

## Тесты

Из корня: `python3 -m unittest homework_2.merge_lists.test_solution -v`.
Или из этой папки: `python3 -m unittest -v`.

Обе реализации проверяются на пустых списках, одном элементе, равных
значениях, отрицательных числах, непересекающихся диапазонах,
чередовании, 200 случайных парах и результате из 100 000 узлов.
Проверяются сортировка, отсутствие циклов, неизменность значений,
точное совпадение идентичностей исходных и выходных узлов и устойчивый
порядок равных значений. Это исключает решение через копирование значений.
