# Validate

Реализация: `validate_stack_sequences(pushed, popped)` в `solution.py`.
Python 3.10+, внешних зависимостей нет. Входные списки не изменяются.
По контракту задачи числа уникальны, popped — перестановка pushed,
1 ≤ n ≤ 100 000. Дополнительно пара пустых списков возвращает True,
разные длины — False. Полная проверка предусловий не нужна алгоритму;
проверка уникальности в интерфейсе нужна для понятных сообщений пользователю.

## Идея и корректность

Проходим pushed слева направо. Добавляем очередное число в рабочий стек.
Пока вершина равна `popped[j]`, извлекаем её и увеличиваем j.
После прохода возвращаем `j == len(popped)`.
Рабочий стек — встроенный Python-список с `append`/`pop` с конца;
это не сторонняя библиотека. Задача о реализации связного стека решена отдельно.

Инвариант: `popped[:j]` уже получен, рабочий стек содержит добавленные,
но ещё не извлечённые элементы в порядке добавления. Если вершина
не совпадает с ожидаемым числом, извлекать её нельзя — единственный
возможный следующий шаг состоит в добавлении. Если совпадает, её можно
извлечь немедленно: при уникальных значениях любое добавление перед этим
закроет нужный элемент, а извлечение нового элемента нарушит ожидаемый
порядок. Поэтому жадные действия не упускают возможного решения.
Если в конце j < n, получить следующий элемент больше невозможно.

## Сложность

Время — **O(n)**: каждый элемент добавляется один раз и извлекается не более
одного раза, несмотря на вложенный `while`. `append` и `pop` с конца работают
за амортизированное O(1). Дополнительная память — **O(n)**: в худшем случае
весь pushed лежит в стеке (popped задан в обратном порядке).

## Пошаговая визуализация

`pushed = [1, 2, 3, 4, 5]`, `popped = [1, 3, 5, 4, 2]`.
В таблице вершина стека **справа**, j — число уже полученных элементов.

| Шаг | Операция | Стек | j | Следующее ожидаемое |
| --- | --- | --- | --- | --- |
| 0 | Начало | [] | 0 | 1 |
| 1 | push(1) | [1] | 0 | 1 |
| 2 | pop() → 1 | [] | 1 | 3 |
| 3 | push(2) | [2] | 1 | 3 |
| 4 | push(3) | [2, 3] | 1 | 3 |
| 5 | pop() → 3 | [2] | 2 | 5 |
| 6 | push(4) | [2, 4] | 2 | 5 |
| 7 | push(5) | [2, 4, 5] | 2 | 5 |
| 8 | pop() → 5 | [2, 4] | 3 | 4 |
| 9 | pop() → 4 | [2] | 4 | 2 |
| 10 | pop() → 2 | [] | 5 | — |

j = 5 = n, ответ **True**.

Для `[1, 2, 3]` и `[3, 1, 2]` после трёх push и pop(3) стек равен
`[1, 2]`, ожидается 1, но вершина 2. Новых входных чисел нет: **False**.
Интерактивный вариант в `../visualization/` показывает вершину слева
и подписывает её `top`.

## Пример использования

```python
from homework_2.validate.solution import validate_stack_sequences

assert validate_stack_sequences([1, 2, 3, 4, 5], [1, 3, 5, 4, 2])
assert not validate_stack_sequences([1, 2, 3], [3, 1, 2])
```

## Тесты

Из корня: `python3 -m unittest homework_2.validate.test_solution -v`.
Или из этой папки: `python3 -m unittest -v`.

Примеры условия, один элемент, пустые входы, разные длины, отрицательные
числа и сохранность входов. Независимый рекурсивный эталон перебирает
все допустимые последовательности операций для n ≤ 7; с ним сравниваются
**все** перестановки выходов. Для n = 100 000 проверяются прямой,
обратный и невозможный порядок. Рекурсия используется только в малом
тестовом эталоне, основное решение итеративное.
