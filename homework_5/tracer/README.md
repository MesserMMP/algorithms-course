# Tracer

## Решение и использование

```python
from homework_5.tracer.tracer import tracer

@tracer
def factorial(n):
    return 1 if n <= 1 else n * factorial(n - 1)

factorial(4)
```

`@tracer(emit=None, on_event=events.append)` отключает печать и собирает структурированные события. `functools.wraps` сохраняет имя, документацию и доступ к исходной функции. Callback получает args/kwargs при входе, result при выходе и error при исключении.

## Идея и корректность

Обёртка читает текущую глубину, сообщает о входе и увеличивает её на время вызова функции. После вычисления сообщает о возврате с результатом. `finally` возвращает ContextVar к прежнему состоянию. Поэтому каждый вложенный вызов получает ровно на единицу большую глубину, а следующий независимый вызов снова начинается с 0. Возвращаемый объект не изменяется. При исключении выводится событие ошибки, само исключение пробрасывается. Обработчики событий должны быть безошибочными; их ошибки тоже пробрасываются.

## Пошаговый пример

```text
→ factorial(4)
  → factorial(3)
    → factorial(2)
      → factorial(1)
      ← factorial = 1
    ← factorial = 2
  ← factorial = 6
← factorial = 24
```

Возврат печатается с тем же отступом, что вход в соответствующий вызов. Живой пример: вкладка Tracer, режим factorial или fibonacci; справа — журнал, слева — стек. На кадре возврата функция ещё видна в стеке.

## Сложность

Дополнительное время O(C + L), где C — число вызовов, L — стоимость форматирования и записи всех сообщений. Рабочая память O(d), где d — максимальная глубина; форматирование одного сообщения дополнительно занимает память его размера. Хранение полного журнала в callback требует памяти всего журнала. Сложность самой декорируемой функции не меняется, кроме этих накладных расходов.
