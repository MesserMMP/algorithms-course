# Домашняя работа 3 · интерактивная визуализация

React 19.3, TypeScript 7, Vite 8 и Motion 13. Версии зафиксированы в lock-файле.
Отдельное приложение: Python-решения не зависят от Node.js или браузера.

## Docker

Из корня репозитория:

```bash
docker compose -f homework_3/visualization/docker-compose.yml up --build -d
# http://localhost:8083

docker compose -f homework_3/visualization/docker-compose.yml --profile tests run --build --rm tests

docker compose -f homework_3/visualization/docker-compose.yml down
```

Сборка: Node.js 24 → статический сайт в nginx. Приложение работает от
пользователя 101, с read-only файловой системой, tmpfs и healthcheck.
Сервис `tests` запускается только явно через профиль и выполняет unittest
в Python 3.13. Docker-контекст — `homework_3`, чтобы включить исходники задач.
Порт можно изменить через `PORT=8093`. Внешние шрифты и CDN не используются.

## Разработка и проверки

Node.js 24+. Из `homework_3/visualization`:

```bash
npm ci
npm run dev          # http://localhost:5175
npm test             # тесты моделей и парсеров
npm run build        # строгий TypeScript + production build
npm run preview      # http://localhost:4175
npx playwright install chromium
npm run test:e2e      # экраны от 320×740 до 1440×1000
```

Playwright сам запускает Vite; скриншоты сохраняются в `test-results/`.
Проверяются ввод, ошибки, результат, переходы, воспроизведение и ширина
страницы на всех вкладках. Vitest проверяет кадры, неизменность истории,
полный перебор маленьких входов Two sum, группировку, коллизии и расширения.

## Управление

1. Выберите задачу слева (на телефоне — сверху).
2. Выберите готовый пример или измените данные и нажмите «Применить».
3. Используйте «Запустить», стрелки, возврат в начало и ползунок шагов.
4. Изучайте содержимое структур и объяснение справа (на телефоне — ниже).
5. Вкладки содержат подробное объяснение, настоящий Python-код и тесты.

Все кнопки доступны с клавиатуры через Tab; ползунок поддерживает стрелки.
Анимации учитывают системную настройку уменьшения движения.
Состояние живёт локально в памяти страницы; после перезагрузки сбрасывается.

## Читаемость и длинные примеры

По умолчанию открываются 10 чисел (20 шагов), 10 слов (21 шаг),
10 операций хеш-таблицы (21 шаг, одно расширение). Дополнительные
развёрнутые сценарии занимают 21–25 шагов; короткие примеры сохранены.
Все готовые сценарии ограничены 25 шагами. Свой ввод может быть длиннее.
Один шаг на скорости 1× занимает 0,8 секунды; доступны 0.5× и 2×.

Формулы сложности — 19 px, названия разделов — 17 px,
вкладки — 13–15 px, основной текст — 14–15 px, вспомогательные подписи — 13 px.
Большие схемы прокручиваются вертикально внутри блока, активное место
и результат автоматически попадают в его видимую область. Прокрутка
доступна колесом, жестом и с клавиатуры после фокусировки схемы.

Браузерные проверки проходят на ширинах 320, 390, 768, 1024 и 1440 px:
все готовые примеры проверяются на каждом шаге, отдельно проверяются
максимальные входы, длинные слова и значения, размеры шрифта формул,
вкладки и работоспособность управления. Скриншоты длинных сценариев
сохраняются в `test-results/`.

## Границы модели

- Two sum: до 32 целых чисел ±1 000 000, k в пределах ±2 000 000.
- Anagrams: до 24 строк, каждая до 32 кодовых точек Unicode.
- Hash table: до 24 операций, целые ключи ±1 000 000, строковые значения
  до 40 UTF-16 единиц; стартовая ёмкость 4. Python по умолчанию использует 8.
- Формат операций: `set 1 apple`, `get 1`, `delete 1`, одна на строку.
- При отсутствии ключа сценарий показывает KeyError и продолжает работу.
- TS использует Python-правило остатка и исключение `hash(-1) == -2`.
- Python-решения не имеют ограничений интерфейса. Сложность указана для
  Python, а хранение кадров требует дополнительной памяти.
- Подсвеченный код — краткая схема; полный исходник находится во вкладке
  «Python-код». Вычисление подписи и добавление слова в группу показаны отдельными шагами.
