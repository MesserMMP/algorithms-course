# Задача 3. Собственная хеш-таблица

Реализация в `solution.py` не использует `dict`, `set`, `tuple` или сторонние
контейнеры для хранения записей. Все контейнеры — **list**:
массив корзин, цепочки в корзинах и записи `[hash, key, value]`.
Ключ и значение — пользовательские объекты, значения могут быть любыми.
Встроенная функция `hash()` вычисляет хеш, но не реализует хранение.

## Запуск и API

```bash
# Из корня репозитория
python3 homework_3/hash_table/solution.py
python3 -m unittest homework_3.hash_table.test_solution -v
```

```python
from homework_3.hash_table.solution import HashTable

table = HashTable(capacity=4)
table.insert("name", "Python")  # table["name"] = "Python"
assert table.search("name") == "Python"  # table["name"]
table.insert("name", "CPython")  # Обновление, размер остаётся 1.
assert "name" in table
assert len(table) == 1
table.delete("name")  # del table["name"]
```

`capacity` и `load_factor` доступны как read-only свойства.
Ёмкость — положительное целое число (bool не допускается), по умолчанию 8.
Неверный тип ёмкости вызывает `TypeError`, неположительное число — `ValueError`.
Нехешируемые ключи, например списки, вызывают `TypeError` до изменения таблицы.
Поиск и удаление отсутствующего ключа вызывают `KeyError`.
`None` — допустимое значение, отличимое от отсутствующего ключа.

## Хранение и коллизии

Индекс: `hash(key) % capacity`. Python-остаток при положительной ёмкости
неотрицателен, поэтому отрицательные хеши корректно обрабатываются.
Каждая корзина — отдельный список (не `[[]] * capacity`).
Разные ключи в одной корзине хранятся цепочкой. При поиске сравниваем
сохранённый хеш, затем идентичность/равенство ключа, а не только хеш.

```text
capacity = 4
set(1, "apple")     set(5, "pear")     set(9, "plum")

0 │ []
1 │ [1, 1, "apple"] → [5, 5, "pear"] → [9, 9, "plum"]
2 │ []
3 │ []
```

Повторная вставка ключа заменяет значение и не увеличивает размер.
Удаление через `pop(index)` убирает запись из цепочки, остальные доступны.
Сложность сдвига элементов списка учитывается в стоимости обхода цепочки.

## Заполнение и расширение

Если **новый** ключ повысит нагрузку `size / capacity` выше 0.75,
удваиваем число корзин и распределяем все записи по новому модулю.
Сохранённый хеш используется повторно. Только после этого вставляем запись.
Существующий ключ не вызывает расширение.

```text
Перед set(2, "kiwi"): (3 + 1) / 4 = 1 > 0.75
Увеличиваем capacity: 4 → 8

1 │ [1, 1, "apple"] → [9, 9, "plum"]
2 │ [2, 2, "kiwi"]
5 │ [5, 5, "pear"]
остальные корзины пусты; load_factor = 4/8 = 0.5
```

[Интерактивная лаборатория](../visualization/README.md) позволяет составить
сценарий `set/get/delete`, увидеть коллизии, обновление, ошибки и расширение.
Для воспроизводимости модель ограничена целочисленными ключами ±1 000 000,
строковыми значениями и стартовой ёмкостью 4. Python-функция `hash(-1)`
равна −2; это исключение учтено в TS-модели. Python-таблица поддерживает
любые hashable-ключи. Хеш строк в Python может отличаться между процессами.

## Корректность

Инвариант: каждая запись лежит в корзине `stored_hash % capacity`, каждый
ключ представлен не более одного раза, `_size` равен числу записей.
Вставка проверяет наличие ключа, обновляет или добавляет ровно одну запись.
Поиск проверяет именно корзину, в которой ключ обязан находиться.
Удаление уменьшает число записей на один. Перехеширование переносит все
записи согласно новому модулю и сохраняет размер. Поэтому все операции
сохраняют инвариант и возвращают/удаляют нужное значение.

Ключ должен иметь стабильный хеш и равенство в течение хранения;
равные ключи обязаны иметь равные хеши. Как у `dict`, `True` и `1`
считаются одним ключом. Проверка идентичности позволяет найти тот же
объект `float('nan')`, хотя он не равен самому себе.

## Сложность и ограничения

Пусть `n` — размер, `c` — ёмкость, `α=n/c`.

| Операция | Ожидаемо при равномерном хешировании | Худший случай |
|---|---|---|
| Поиск, удаление, `in` | O(1 + α), при α ≤ 0.75 — O(1) | O(n) |
| Вставка без расширения | O(1 + α) | O(n) |
| Расширение | O(n + c) | O(n + c) |
| Вставка с учётом расширений | Амортизированное O(1) | O(n + c) за операцию |
| `len`, свойства | O(1) | O(1) |

Создание таблицы стоит `O(c)`. Память `O(n + c)`, временная память при
расширении также `O(n + c)`. Амортизация вставки основана на геометрическом
росте: суммарная стоимость переносов при последовательных вставках — O(n).
Хеширование и сравнение считаются O(1); для сложных ключей их стоимость
добавляется. Все ключи с одинаковым хешем деградируют до одной цепочки.

После удалений ёмкость не уменьшается: это упрощает поведение и предотвращает
частые перераспределения при чередовании операций, но сохраняет выделенную
память. Таблица не обеспечивает порядок итерации и синхронизацию потоков.

## Тесты

Вставка, перезапись, `None`, удаление, повторное удаление, отсутствующие ключи,
синтаксис `[]`, отрицательные и огромные ключи, строки, кортежи, bool/int,
NaN по идентичности, неправильная ёмкость, нехешируемые ключи.
Специальные объекты с одинаковым отрицательным хешем проверяют длинную цепочку,
поиск после расширений и удаление первого/среднего/последнего элемента.
10 000 случайных операций сравниваются с `dict` (только в тестовом эталоне).
100 000 записей проходят многократное расширение, поиск и полное удаление;
отдельно проверяется, что внутренние контейнеры — списки.
