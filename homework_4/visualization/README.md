# Домашняя работа 4 · визуализация бинарных деревьев

Отдельное приложение на React 19.3, TypeScript 7 и Vite 8.
Схема дерева построена в SVG; переходы и оформление реализованы на CSS.
Зависимости закреплены в `package-lock.json`; Python-решения лежат
в соседней папке [`Binary_Tree/`](../Binary_Tree/README.md).

## Запуск

Из корня репозитория:

```bash
docker compose -f homework_4/visualization/docker-compose.yml up --build -d
# http://localhost:8084/visualization/
```

Сервис `tests` запускается явно и выполняет Python unittest:

```bash
docker compose -f homework_4/visualization/docker-compose.yml --profile tests run --build --rm tests
docker compose -f homework_4/visualization/docker-compose.yml down
```

Docker собирает приложение в Node.js 24 и раздаёт статические файлы nginx.
Контекст сборки — весь `homework_4`, чтобы включить настоящие Python-файлы
в интерфейс через raw-импорты. Контейнер работает без root, с read-only
файловой системой, tmpfs и healthcheck. Порт хоста меняется переменной `PORT`.

Локальная разработка с Node.js 24+, из `homework_4/visualization`:

```bash
npm ci
npm run dev          # http://localhost:5176
npm test             # Vitest: модели, кадры и ввод
npm run build        # TypeScript и production build
npm run preview      # http://localhost:4176
npx playwright install chromium
npm run test:e2e      # Chromium, пять размеров экрана
```

## Что показывает приложение

- **Tree Traversal:** свойства BST, выбор ветви при вставке и шесть обходов.
  У прямых обходов сначала рассматривается левый ребёнок, у обратных — правый;
  положение посещения самого узла задаётся preorder, inorder и postorder.
- **Validate BST:** допустимый интервал узла, который сужается при спуске.
  Нарушение может происходить относительно далёкого предка, даже когда
  сравнения с непосредственным родителем проходят.
- **Balanced Binary Tree:** высоты левого и правого поддеревьев,
  разность высот и результат для каждого узла после обработки детей.

Выберите задачу и пример, затем переходите по шагам вручную или включите
воспроизведение. Можно остановить просмотр, вернуться назад, изменить
скорость и применить собственные данные. Объяснение текущего шага помогает
сопоставить подсветку дерева с действием алгоритма.

Обход выбирается тремя карточками с мини-схемами: preorder, inorder и
postorder. Переключатель «Сначала левое / Сначала правое» задаёт обычный
или reverse-порядок. На карточках цифры показывают посещение трёх узлов;
на основной схеме метки № показывают уже выполненный порядок посещения.
Карточками можно управлять стрелками клавиатуры, Home и End.

Готовые деревья собраны в списке «Пример дерева», собственный ввод —
в раскрывающемся блоке «Свои данные». Переход показывает широкая мягкая
янтарная волна внутри рёбер: у каждой связи одна линия, без стрелок и движущихся
объектов. Ребро утолщается с 2 до 4.8 единиц SVG по мере прохождения волны,
получает мягкий янтарный ореол и возвращается к исходной толщине. Насыщенный
цвет сохраняется вдоль пути; градиент движется с плавным ускорением и затуханием,
затем возвращается к нейтральному виду. Текущий узел отмечен мягкой янтарной
заливкой, контуром, тенью и коротким подчёркиванием; обработанные узлы остаются зелёными.
Заливка, контур и отметка посещения включаются, когда видимая передняя часть
волны достигает карточки. При перемотке незавершённая анимация отменяется.
На скорости 1× волна занимает 1350 мс, появление акцента карточки — 220 мс; на 2×
длительности уменьшаются вдвое. Шаг длится 1500 мс на 1×, чтобы волна успела завершиться.
Настройка reduced motion отключает волну и плавные переходы; статический
контур текущего узла сохраняется.

Стартовые примеры занимают 16 шагов для обхода, 18 для вставки,
19 для проверки BST и 19 для проверки баланса. Шаг 0 показывает исходное
состояние. При скорости 1× шаг занимает 1500 мс; доступны 0.5× и 2×.

Нажатие на узел открывает сведения о его значении и детях, а также
известные на текущем шаге границы или высоту. Масштаб схемы регулируется
от 75% до 150%; кнопка «Вписать дерево» подбирает масштаб в этих пределах.
Для больших и глубоких деревьев внутри схемы доступна локальная
прокрутка; активный узел автоматически попадает в видимую область.

Python-исходники импортируются из папки задачи при сборке.
Вычисления в браузере выполняет TypeScript-модель: запуск интерфейса
не запускает Python. Python-тесты проверяются отдельной командой выше.

## Проверка интерфейса

Playwright сам запускает dev-сервер и использует экраны
1440×1000, 1024×768, 768×1024, 390×844 и 320×740.
Материалы прогонов находятся в `test-results/`, отчёты — в `playwright-report/`;
они исключены из Git и Docker-контекста.

Проверки включают готовые примеры на каждом шаге, точные результаты всех
шести обходов, вставку, ошибки ввода, вкладки, управление и длинные подписи.
Для desktop и mobile сохраняются снимки середины и конца стартового
примера каждой задачи: полная страница и область работы алгоритма.

## Формат и ограничения собственного ввода

- Для вставки и обходов: JSON-массив, не более 15 целых значений.
  Повторы игнорируются при построении строгого BST.
- Для проверок: JSON-массив в компактном порядке по уровням, не более
  31 позиции с учётом `null` и не более 15 существующих узлов.
  `null` занимает место ребёнка, но не имеет собственных дочерних позиций.
  Например, `[8, 4, 12, null, 6]` задаёт правого ребёнка 6 у узла 4.
- Значения — безопасные целые JavaScript от −9007199254740991
  до 9007199254740991 включительно. Дроби и небезопасные числа отклоняются.
- `[]` задаёт пустое дерево. Для проверки дерева также допустим `[null]`.

Эти ограничения нужны для наглядности интерфейса и точности JavaScript.
Python-решения не имеют указанных лимитов количества узлов и размера целых
чисел. Полная история кадров визуализации расходует дополнительную память
сверх указанной сложности самих алгоритмов.

## Файлы инфраструктуры

```text
package.json           # Команды и зависимости
vite.config.ts         # Сборка со ссылками относительно /visualization/
vitest.config.ts       # Проверки src/**/*.test.ts
playwright.config.ts   # Браузерные проверки e2e/ на пяти размерах экрана
Dockerfile             # Node.js → nginx
nginx.conf             # Раздача /visualization/ на порту 8084
docker-compose.yml     # Приложение и отдельный профиль Python-тестов
```
