# Compare · рекурсивные сортировки

Обе функции возвращают новый список по возрастанию. Например, для `[4, 1, 4, 2, 3, -1, 2]` результат равен `[-1, 1, 2, 2, 3, 4, 4]`. Для замера одного вызова оберните функцию декоратором.

```python
from homework_6.compare.sorts import mergesort, quicksort
from homework_6.compare.timing import timed

numbers = [4, 1, 4, 2, 3, -1, 2]
measure = timed(quicksort)
result = measure(numbers)  # Печатает время в мс и возвращает отсортированный список.
assert result == mergesort(numbers)
```

## Как получаем результат

**Merge sort.** Функция делит участок пополам, пока в нём не останется один элемент. При возврате очередные две половины уже упорядочены. Переносим в результат меньший из двух ещё не взятых элементов. Каждый шаг записывает наименьшее оставшееся значение, поэтому результат слияния тоже упорядочен. При равенстве выбираем значение из левой половины и сохраняем исходный порядок равных элементов.

**Quick sort.** Опорой служит первый элемент участка. Во время прохода поддерживаем четыре последовательные области: меньше опоры, равные, ещё не просмотренные и больше. Обмен отправляет элемент в нужную область, а неизвестная область сокращается. По завершении прохода равные уже заняли окончательные позиции по значению. Осталось упорядочить участки слева и справа. Для меньшего вызываем функцию рекурсивно, для большего продолжаем цикл в том же вызове.

## Один массив, два способа сортировки

Метки `4а` и `4б` обозначают два вхождения одного числа. Индексы начинаются с нуля, правая граница участка исключена.

| Merge sort | Состояние обрабатываемого участка |
|---|---|
| Деление всего массива | `[4а, 1, 4б] │ [2, 3, -1, 2]` |
| Возврат из левой ветви | `[4а] + [1, 4б] → [1, 4а, 4б]` |
| Возврат из правой ветви | `[2, 3] + [-1, 2] → [-1, 2, 2, 3]` |
| Слияние половин | `[-1, 1, 2, 2, 3, 4а, 4б]` |

| Quick sort | Массив после разбиения |
|---|---|
| Опора 4 на всём массиве | `[1, 2, 3, -1, 2] │ [4, 4] │ []` |
| Опора 1 на первых пяти элементах | `[-1] │ [1] │ [3, 2, 2]` · хвост `[4, 4]` готов |
| Опора 3 на участке `[2, 5)` | `[2, 2] │ [3] │ []` |
| Опора 2 на участке `[2, 4)` | Оба значения равны опоре. Итог `[-1, 1, 2, 2, 3, 4, 4]` |

## Время и память

| Метод | Время | Дополнительная память |
|---|---|---|
| Merge sort | O(n log n) при любом порядке. На каждом из O(log n) уровней сливаем в сумме O(n) значений | O(n) на буфер, O(log n) на стек вызовов |
| Quick sort | В среднем O(n log n) для случайной перестановки различных элементов. В худшем случае O(n²). Для одинаковых элементов O(n) | O(log n) на стек даже в худшем случае. Рекурсивный вызов получает не более половины текущего участка |

Каждая функция дополнительно создаёт список результата из n элементов. Оценки относятся к работе без записи состояний. Если передать `on_event=frames.append`, каждый кадр хранит снимок массива для пошагового просмотра.

## Эксперимент и тесты

`python3 -m homework_6.compare.benchmark` измеряет обе функции на одних и тех же данных. Декоратор использует монотонный счётчик `perf_counter_ns` и возвращает результат вызываемой функции. На одинаковых значениях quicksort завершает работу после первого прохода. На убывающем массиве из различных чисел первая опора каждый раз максимальна, а следующий участок короче лишь на один элемент. Число просмотренных позиций растёт как n + (n − 1) + … + 2. [Методика и измеренные результаты](BENCHMARK.md).

`python3 -m unittest homework_6.compare.test_compare -v` проверяет пустой и одноэлементный массивы, повторы, отрицательные и большие числа, глубокую последовательность односторонних разбиений, декоратор и корректность замеров. Стабильность слияния дополнительно проверяется в [тестах Iterative](../iterative/test_iterative.py).
