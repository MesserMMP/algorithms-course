# Сравнение времени рекурсивных сортировок

Из корня репозитория выполните:

```sh
python3 -m homework_6.compare.benchmark
```

Программа измеряет один вызов сортировки целиком, включая копирование входа. Декоратор `@timed` читает монотонный счётчик `perf_counter_ns()` перед вызовом и после него, возвращает результат функции и печатает длительность в миллисекундах. Форма `@timed(report=callback)` передаёт имя функции и число наносекунд обработчику. Декоратор сохраняет имя и документацию функции. При исключении он тоже регистрирует время и пропускает исключение дальше.

Обе реализации получают одинаковые массивы. Генерация, проверка результата, прогрев и подготовка отчёта проводятся за пределами интервала замера. Трассировка при измерениях отключена. Каждый метод запускается один раз для прогрева и пять раз для измерения. Порядок методов чередуется. В таблицу попадает медиана пяти длительностей. Для случайной перестановки фиксирован seed 42.

| Вход | Откуда берётся разница |
| --- | --- |
| Случайная перестановка | Для quicksort первый элемент случайно перемешанного диапазона обычно даёт две непустые части. Ожидаемое время и у quicksort, и у mergesort порядка O(n log n). |
| Все элементы равны | Трёхпутевое разбиение quicksort за один проход относит весь массив к блоку равных, и сортировка заканчивается за O(n). Mergesort продолжает сливать части на каждом из O(log n) уровней. |
| Строго по убыванию | Первый элемент является максимумом. Реализация разбиения оставляет остальные элементы в убывающем порядке. Длины следующих разбиений равны n−1, n−2 и далее до 2. Суммарное время quicksort достигает O(n²), тогда как у mergesort сохраняется O(n log n). |

Медианы зависят от машины, версии Python и нагрузки. Тесты проверяют правильность результатов и вычисление медиан на контролируемых показаниях часов. Фиксированного порога скорости в тестах нет.

Пример запуска на macOS arm64, CPython 3.14.0. В каждой строке 1200 элементов, время приведено в миллисекундах.

| Набор | Mergesort | Quicksort |
| --- | ---: | ---: |
| Случайный порядок | 1,387 | 1,391 |
| Все значения равны | 1,207 | 0,074 |
| По убыванию | 1,200 | 56,142 |

В этом запуске quicksort быстрее примерно в 16 раз на равных значениях и медленнее примерно в 47 раз на убывающем массиве.
